M11 scope

Implemented in M11

  • Alpine Linux APK — .apk packages (amd64 + arm64) produced by goreleaser via nfpm. make apk and make apk-arm64 targets added.
  • AUR PKGBUILD — packaging/aur/PKGBUILD + .SRCINFO for Arch Linux. CI patches pkgver/sha256sums on release.
  • Helm chart (charts/skoed/) — deploys as Deployment or DaemonSet on Kubernetes. Published to ghcr.io/ashmonger/charts/skoed.
  • Proxmox script in releases — scripts/proxmox-create.sh attached to every GitHub Release via goreleaser extra_files.
  • Full documentation — 15 stub pages replaced with real content across install, cluster, configuration, operations, and reference sections.

Not implemented in M11

  • Publishing to the official Debian/Ubuntu PPA (requires Debian Developer sponsorship)
  • Publishing to Alpine Linux's official edge repository (requires Alpine maintainer)
  • Live AUR push (requires AUR_SSH_PRIVATE_KEY secret)

Limitations

  • DaemonSet mode in Helm does not support PVCs — data volume falls back to emptyDir
  • AUR PKGBUILD uses SKIP checksums as placeholders until a release tag exists

Retrospective note

M11 — Distribution & Documentation addressed operator onboarding friction. The Alpine APK was the most important deliverable for the Proxmox cluster use-case: node-2 runs Alpine Linux and previously required manual binary extraction. With the .apk package, installation is a single apk add command. The Helm chart enables Kubernetes deployments without manual manifest authoring. Fifteen documentation stub pages were filled in, closing the gap between the feature set (M1–M10) and operator-facing guidance. The two CI-only tests (Helm chart Kubernetes install, GHCR publish) are correctly skipped in local acceptance runs and validated end-to-end by the release workflow.
