How DoT and DoH Work in skoed

DNS-over-TLS (DoT)

  • URL: tls://host:port
  • Port 853 added if omitted
  • Transport: dns.Client{Net:"tcp-tls"}
  • TLS ServerName = hostname from URL
  • ?skip_verify=true for self-signed

DNS-over-HTTPS (DoH)

  • URL: https://host/path
  • Default: RFC 8484 POST
  • ?method=get → base64url GET
  • Content-Type: application/dns-message
  • ?skip_verify=true for private CAs

Plain UDP/TCP (fallback)

  • URL: host:port
  • UDP first; TCP on truncation
  • Can coexist with DoT/DoH
  • Tried in declaration order
  • SERVFAIL if all fail
// Forwarder dispatch — forwarder.go
for _, u := range cfg.UpstreamResolvers {
    switch {
    case strings.HasPrefix(u, "tls://"):
        fns = append(fns, makeDotFn(u, timeout))   // DNS-over-TLS
    case strings.HasPrefix(u, "https://"):
        fns = append(fns, makeDohFn(u, timeout))   // DNS-over-HTTPS (RFC 8484)
    default:
        fns = append(fns, makePlainFn(u, timeout)) // plain UDP + TCP fallback
    }
}

Implemented Scope

  • ✅ DNS-over-TLS (DoT) — tls://host:port, port 853 default, TLS cert verified vs system CA
  • ✅ DNS-over-HTTPS (DoH) — RFC 8484 POST (default) and GET, https://host/path
  • ✅ skip_verify query param — operator-controlled TLS certificate bypass
  • ✅ Mixed upstream lists — plain UDP, DoT, DoH can coexist in one config; fallback in order
  • ✅ SERVFAIL on total failure — all upstreams fail → SERVFAIL to DNS client
  • ✅ Scheme validation at PATCH — unsupported schemes (ftp://) rejected HTTP 400
  • ✅ Config persistence via Raft — bbolt store, replicated to all nodes
  • ✅ API transparency — GET /api/v1/settings returns full URL with scheme

Out of Scope

  • ⬜ Per-query upstream selection (single list applies globally)
  • ⬜ DNSCrypt upstream support
  • ⬜ Automatic upstream discovery (DHCP / OS resolver)
  • ⬜ DoT/DoH connection pooling (each query opens a new connection)
  • ⬜ skoed itself as DoT/DoH server for clients (M4, already shipped)
