⚠ Correctness fix included

DeleteProfileAllowlistEntry was missing cache.PurgeDomain(domain) after removal. Without it, a deleted allowlist entry continued resolving as NOERROR from cache until the TTL expired — silently defeating the delete. Fixed in this milestone; covered by TestPerProfileAllowlistDeletePurgesCache.

What changed

  • !
    fix DeleteProfileAllowlistEntry — cache purge Added cache.PurgeDomain(domain) after UpsertProfile. Matches behaviour already present in AddProfileAllowlistEntry and global DeleteAllowlistEntry.
  • +
    new Handler: ReplaceProfileAllowlist PUT /api/v1/profiles/{id}/allowlist — decodes []string body, validates entries, replaces via UpsertProfile, purges cache for removed domains.
  • +
    new Route in app.go r.Put("/api/v1/profiles/{id}/allowlist", a.forward(h.ReplaceProfileAllowlist)) — placed between existing POST and DELETE routes.
  • +
    new Web UI: Profile detail Allowlist tab Modal in Profiles.vue gains Settings / Allowlist tabs (edit mode only). Tab shows entry list, per-entry delete, wildcard badge, add-domain input, and entry count badge.
  • +
    new API client: replaceProfileAllowlist Added to endpoints.ts. Calls putJSON(`/api/v1/profiles/${id}/allowlist`, domains).
  • +
    new Harness: NodeConfig.Env Added Env []string to NodeConfig and wired into cmd.Env in startNode. Allows parallel tests to set SKOED_TEST_MODE=1 per-subprocess without t.Setenv.

  • Allowlist scheduling and time-gated entries
