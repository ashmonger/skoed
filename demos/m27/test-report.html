What changed

  • !
    Bug fix: DeleteProfileAllowlistEntry — cache purge Added cache.PurgeDomain(domain) after UpsertProfile. Matches the behaviour already present in AddProfileAllowlistEntry and global DeleteAllowlistEntry.
  • +
    New handler: ReplaceProfileAllowlist PUT /api/v1/profiles/{id}/allowlist — decodes []string body, validates entries, replaces via UpsertProfile, purges cache for removed domains.
  • +
    Route registered in app.go r.Put("/api/v1/profiles/{id}/allowlist", a.forward(h.ReplaceProfileAllowlist)) — placed between existing POST and DELETE routes.
  • +
    Web UI: Profile detail Allowlist tab Modal in Profiles.vue gains Settings / Allowlist tabs (edit mode only). Tab shows entry list, per-entry delete, wildcard badge, add-domain input, and entry count badge.
  • +
    API client: replaceProfileAllowlist Added to endpoints.ts. Calls putJSON(`/api/v1/profiles/${id}/allowlist`, domains).
  • +
    Harness: NodeConfig.Env Added Env []string to NodeConfig and wired into cmd.Env in startNode. Allows parallel tests to set SKOED_TEST_MODE=1 per-subprocess without t.Setenv.

Not implemented

  • Allowlist sharing between profiles
  • Allowlist scheduling and time-gated entries
  • Per-entry metadata (notes, expiry, tags)
  • Proxmox real-environment validation (pending UoR)
  • Dedicated profile detail route (modal-based edit retained)
