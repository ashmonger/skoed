M3.5 scope

Implemented in M3.5

  • GET /api/v1/clients/{ip}/doh-status
    Rolling-window DoH probe results per client IP, provider inference (cloudflare/google/quad9/adguard/opendns/nextdns/controld), Dashboard DoH alert card
  • Firewall rule generators
    iptables, nftables, MikroTik, OpnSense, UniFi — subnet scope, profile scope, all scope, reject action opt-in, snapshot provenance header
  • Curated DoH-resolver-IP database
    Auto-refresh daily (leader only), replicated via Raft, stale flag after 7 days, upstream failure keeps last good snapshot, retry with backoff
  • Web UI firewall rules panel
    Clients row action, platform tabset modal, copy to clipboard, stats subnet callout, stale snapshot banner

Not implemented in M3.5

  • DHCP client enrichment (M3.6)
  • DoH/DoT server (M4)
  • Automated firewall rule push to router (manual copy only)

Limitations

  • DoH status endpoint served from local node state — sub-second staleness window on followers
  • Stale snapshot still served (degraded mode) when upstream is unreachable
  • Resolver DB refresh is leader-only; followers get snapshot via Raft replication
