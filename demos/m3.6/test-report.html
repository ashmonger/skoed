M3.6 scope

Implemented
  • Kea DHCP connector — reads leases from GET /api/v4/leases4, handles Basic Auth, maps client-id + MAC + hostname into skoed client identity
  • dnsmasq connector — parses /var/lib/misc/dnsmasq.leases flat-file format, skips expired leases
  • Generic HTTP-JSON connector — configurable endpoint, configurable field mapping, automatic retry on non-200
  • Lease cache refresh — configurable interval (default 60 s); all connectors share the same cache layer
  • Client identity enrichment — query log entries decorated with hostname; fallback to IP when no lease matches
  • Profile matching by DHCP identity — match by client_id, MAC, or hostname; priority order respected
  • Anti-spoof detector — MAC-change, client_id-change, hostname-change anomalies surfaced; acknowledgment endpoint; anomaly retention
  • Spoof anomaly dashboard card — new-client and anomaly counts; hostname-change classified as INFO (not WARN)
Not implemented
  • ISC dhcpd lease file connector (EOL technology, carve-out)
  • DHCPv6 lease support
  • Auto-block on spoof detection (alert-only in M3.6)
  • Multi-connector fan-out (single active connector per node)
Limitations
  • Lease cache is node-local; not replicated via Raft — followers independently poll their configured DHCP source
  • Spoof detection based on in-memory comparison only; no persistent anomaly history across restarts without explicit flush
  • Kea connector requires Kea 2.x API; earlier versions not tested

Retrospective note

M3.6 closes the client-identity gap. Kea, dnsmasq, and generic HTTP-JSON connectors provide a unified lease cache that decorates query-log entries with hostnames and enables profile assignment by MAC, client_id, or hostname. The anti-spoof detector watches for MAC-change and client_id-change anomalies across lease-cache refreshes; hostname changes are classified as INFO. The acknowledgment endpoint clears reviewed anomalies. FS-SpoofDashboardAlert is verified manually (UI-only behavior — no programmatic test vector exists). Full acceptance suite (M1 → M3.6): CI green; 3 in-process SKIPs for tests requiring a real Kea server are expected and documented.
