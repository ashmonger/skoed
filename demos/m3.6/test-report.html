M3.6 scope

Implemented in M3.6

  • 3 DHCP connectors
    Kea (REST API with auth), dnsmasq (lease file parser, skips expired), generic HTTP-JSON with retry
  • Lease cache with periodic refresh
    Configurable refresh interval, malformed lease entries skipped gracefully
  • Client identity enrichment
    Query log shows hostname, falls back to IP when no lease, profile matching by client_id / MAC / hostname with priority order
  • Anti-spoof detector (Layer 1+2)
    MAC changed for known client_id, client_id changed for known MAC, new MAC for existing hostname — anomaly retention and acknowledgment API
  • Clients page in web UI
    Enriched client list with lease data

Not implemented in M3.6

  • DoH/DoT server (M4)
  • Automated anomaly alerting via webhook (manual acknowledgment only)
  • DHCP connector for ISC DHCP (dhcpd)

Limitations

  • Hostname change is logged as info, not an anomaly (by design)
  • Lease cache is per-node; not replicated across cluster (client identity is node-local)
  • Generic HTTP-JSON connector requires external implementation of the lease API
