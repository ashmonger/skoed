Design note — dedup via content hash

Scheduled backup deduplication uses SHA-256 of exported config bytes, not the Raft applied index. The applied index advances on every Raft log entry including background DoH resolver heartbeats (CmdDohResolverSnapshotReplace), so an index-based comparison would generate a spurious backup every interval even with no real config change. Content hashing is correct and independent of Raft activity.

What changed

  • +
    new config.ExportWithPassphrase / ImportWithPassphrase age-encrypted export/import using filippo.io/age (scrypt KDF, AES-256-GCM). Wrong passphrase returns wrapped error containing "invalid passphrase or corrupted archive".
  • +
    new config.BackupScheduler Goroutine loop reading BackupConfig from bbolt each iteration. SHA-256 content-hash dedup skips backup when exported bytes match last_content_hash. Prunes oldest files when retain_count exceeded.
  • +
    new bbolt buckets: config_backups, config_backup_settings Node-local storage (not replicated via Raft) for backup entries and scheduler settings. last_content_hash key stored alongside entries.
  • +
    new Routes: backup CRUD + diff PUT /api/v1/settings/backup, GET /api/v1/config/backups, GET /api/v1/config/backups/{id}/download, POST /api/v1/config/backups/trigger, POST /api/v1/config/diff.
  • +
    new config.DiffArchives Reads two archives, compares blocklists (name, url), allowlists (domain), local DNS entries (host, ip), and settings (upstream resolver). Returns structured DiffResult with added/removed/changed sections.

Not implemented (out of scope)

  • Database-level incremental backups (full snapshots only)
  • Remote backup targets (S3, SFTP) — post-M31
  • Backup failure webhook event — post-M31
  • Backup encryption key rotation after passphrase change
  • Restoring a backup without service interruption
