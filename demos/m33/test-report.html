Behaviour change: AAAA → NXDOMAIN (not SERVFAIL)

In M26, AAAA queries on blocked domains in redirect mode returned SERVFAIL when no redirect_address_v6 was set. M33 changes this to NXDOMAIN per FS-BlockPageIPv6NotConfigured — a more precise response that tells the client "this domain has no IPv6 address" rather than "server error". The existing TestBlockPageRedirectServfailAAAA test was updated accordingly.

What changed

  • +
    new ProfileBlockPageConfig struct in config Fields: Title, Message, ContactEmail, LogoURL, BypassPasscode. Attached to Profile via BlockPage *ProfileBlockPageConfig.
  • +
    new RedirectAddressV6 in BlockPageConfig IPv6 address returned for AAAA queries on blocked domains in redirect mode.
  • +
    new Block page server: per-profile content + custom template ?client_ip= triggers profile lookup for per-profile title/message. SetCustomTemplate / ClearCustomTemplate for runtime template swap.
  • +
    new POST /api/v1/bypass handler Verifies bypass_passcode, calls SetProfilePause for the requested duration. Returns {profile_id, expires_at}.
  • +
    new Template routes: PUT / DELETE /api/v1/blockpage/template Upload or remove a custom HTML template. DELETE reverts to built-in layout.
  • !
    fix AAAA blocked without v6 addr → NXDOMAIN (was SERVFAIL) DNS handler now returns RcodeNameError when redirect_address_v6 is not configured, matching FS-BlockPageIPv6NotConfigured.

Not implemented (out of scope)

  • Per-client bypass (allowlist entry) — current bypass pauses whole profile via SetProfilePause
  • Rich media block pages (video, iframe) — plain HTML only
  • Per-domain block page granularity (per-profile is the granularity)
  • HTTPS / ACME for the block page redirect server — post-M33
  • Bypass button rate-limiting (passcode controls access)
