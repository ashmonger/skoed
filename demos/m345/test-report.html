Root Cause & Fix Applied

hashicorp/raft v1.7.3 does not persist lastApplied to disk. With the default SnapshotThreshold=8192 and only ~663 log entries, no snapshot was ever taken — causing a full 30-second log replay on every restart. The API served stale mid-replay values when polled at T+8 s. Fix: SnapshotThreshold=64 + SnapshotInterval=30s in cluster/raft.go. After the first snapshot is taken, restarts replay ≤64 entries (near-instant). All three nodes confirmed snapshotted before this test run.
