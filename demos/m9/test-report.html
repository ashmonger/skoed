Milestone Scope

Implemented
  • SkoedCluster CRD (skoed.io/v1alpha1) — manages a skoed cluster on Kubernetes; fields: replicas, image, storage, dns, api, tls, adminSecretRef, resources
  • StatefulSet provisioning — creates StatefulSet + headless Service + ConfigMap + auto-generated bootstrap Secret; init container writes per-pod node.yaml (pod-0 = leader, pods 1+ = followers with bootstrap token)
  • Scale up — increment replicas; new pods auto-enroll via bootstrap token
  • Scale down — operator calls DELETE /api/v1/cluster/nodes/{id} for each removed pod; transfers leadership if the pod being removed is current leader
  • Status conditions — Ready and Quorum conditions; .status.leader, .voters, .readyReplicas synced every 30s; kubectl get skoedcluster shows Replicas/Ready/Leader columns
  • ACME cert rotation — operator annotates StatefulSet pod template when cert expiry < 30 days to trigger rolling restart
  • Helm fallback unaffected — existing deploy/helm/skoed/ chart is unaffected; operator selects only pods with label skoed.io/cluster=<name>
  • Operator Helm chart — deploy/helm/skoed-operator/ with Deployment, ServiceAccount, ClusterRole, ClusterRoleBinding, both CRDs
Not Implemented
  • SkoedNode status population — CRD registered but reconciler does not yet create individual SkoedNode objects per pod
  • Web UI integration for operator-managed clusters
  • Rolling binary upgrade safety validation — changing spec.image triggers StatefulSet rolling update but Raft safety is not verified by the operator
  • cert-manager integration — ACME managed directly inside skoed pods; operator only triggers restarts
Limitations
  • Bootstrap token rotation requires deleting the Secret; operator regenerates on next reconcile
  • ACME HTTP-01 challenge requires port 80 reachable on pod IP; may conflict with network policies
  • Scale-down node deletion calls are best-effort; unreachable pods eventually converge after deletion

Retrospective

M9 brings skoed into Kubernetes via a controller-runtime operator. The SkoedCluster CRD abstracts a full skoed cluster as a Kubernetes resource: the operator provisions the StatefulSet, writes per-pod node.yaml via init containers, manages scale-up/scale-down with graceful Raft node removal, and rotates ACME certs via rolling restarts. The existing Helm chart for direct deployments is unaffected. CRD schema, printer columns, PVC volume claim templates, and Helm fallback isolation are all verified by the acceptance test suite.
