Verdict

  • The DNS path runs out of memory under sustained load. From about 5,000 qps per node, a 2 GB container fills RAM and swap within seconds to a minute and skoed is OOM-killed. In the 15-minute soak, every node stopped answering after 2–5 minutes and answered nothing for the remaining 10 minutes; 45 minutes after the load stopped, the nodes still held 2.0 GB and used about one core each.
  • Throughput is capped at about one core per node (17,000–24,000 qps cached, 5,500–7,500 qps cache miss), with p50 0.29 ms at 5,000 qps.
  • Raft writes get slower as custom DNS records accumulate: write latency grows linearly with the record count, and each write adds 45–56 KB to the Raft log.
  • Blocklists, failover and mTLS behave well: 2M domains on every node in 5.1 s, a new leader in 1.7–3.4 s with no DNS loss, mTLS within noise.

Mixed load on all five nodes, target 4,000 qps per node (about half of the T3 total), public lists only.

RAM + swap per container, during and after the soak

n1n2n3n4n5OOM kill of skoed
  • Every node served the target in the first minute, then collapsed: from minute 5 to the end, no node answered any query. dnsperf's averages (295–628 qps, 2.4–5.5 % loss) hide this, because it sends few queries once they all time out.
  • All nodes reached 1.9 GB in the first minute and stayed at 2.0 GB with full swap and 100–120 % CPU for the whole run.
  • The memory is not released when the load stops. n2 was killed at 13:46:49, 10 minutes after the load ended. The four other nodes kept 2.0 GB of RSS with swap full, still slowly growing, and used 88–112 % CPU with no DNS load until the cluster was rebuilt for T6, 45 minutes later.
  • Disk did not grow (/var/lib/skoed 19.6 MB): the query log is in memory only. The blocked share of the mix (its list had been deleted) and the write loop (script error) are not valid.

Findings

  1. Memory grows without limit on the DNS path under load. RSS climbs at 50–200 MB/s from 5,000–10,000 qps and is not released when the load stops: 45 minutes after the soak, four nodes still held 2.0 GB, swap full, and used 88–112 % CPU with no DNS load. 
    Memory cgroup out of memory: Killed process 33539 (skoed) total-vm:3876392kB, anon-rss:2053504kB
    Not confirmed (the goroutine dump was truncated by journald, no heap profile). Most likely: every query goes through QueryLog.Append (apps/skoed/internal/log/query.go:84), which shifts the 10,000-entry ring with copy() under one global mutex; miekg/dns runs each query in its own goroutine, so goroutines pile up when queries arrive faster than the mutex lets them through. That would also explain the one-core ceiling. Aggregator.Observe (apps/skoed/internal/log/aggregates.go:108) also keeps every distinct domain of the hour in a map.
  2. A node answers DNS before its blocklists are loaded, after a rejoin (3 s in T8) and after every restart, so blocked names resolve during that time.
  3. Each local-dns write adds 45–56 KB to the Raft log, and the write cost grows linearly with the number of records (132 → 11 writes/s).
  4. OISD in auto format loads 11 junk entries. detectFormat (apps/skoed/internal/filter/engine.go:253) decides on the first line that is not a comment; in OISD that is [Adblock Plus], which contains a space, so the list is parsed as a hosts file and every ||domain^ rule is dropped.
  5. A deleted URL list's file stays on disk, and after a restart blocklistsync logs copy "syn1m" … leader answered 404.
  6. After a container reboot, skoed starts before the container has its IP (the stock unit uses the same After=network-online.target).
  7. Raft logs at DEBUG level in the journal.

Not covered

  • Latency above 10,000 qps (stopped by loss) and the write loop of T10.
  • DoH, DoT and DNSCrypt; DHCP; the web UI (this build has none).
  • A load generator on separate hardware.
