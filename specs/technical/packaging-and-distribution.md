## 1. Alpine APK package

### 1.1 Build toolchain

nfpm (via goreleaser) supports the `apk` format natively. Adding `apk` to the
`formats` list in the `nfpms` section of `.goreleaser.yaml` is the only
configuration change required.

**Change to `.goreleaser.yaml`:**

```yaml
nfpms:
  - id: skoed
    formats:
      - deb
      - apk      # ← add this
    # … rest unchanged
```

### 1.2 Artifact names

goreleaser produces `skoed_<version>_amd64.apk` and `skoed_<version>_arm64.apk`.
Both are attached to the GitHub Release automatically.

### 1.3 Alpine package contents

| Path | Purpose |
|------|---------|
| `/usr/bin/skoed` | Static binary |
| `/etc/skoed/config.yaml` | Default config (noreplace) |
| `/var/lib/skoed/` | Data dir (mode 0700, skoed:skoed) |
| `/var/log/skoed/` | Log dir (mode 0750, skoed:skoed) |

Note: `apk` format does not support OpenRC init scripts via nfpm; operators on
Alpine should use the provided Docker image or add a custom OpenRC service file.
The `skoed.service` systemd unit is not installed on Alpine (nfpm skips it when
the target format does not support systemd). If Alpine-with-systemd becomes a
supported target in a future milestone, an init script can be added.

### 1.4 Pre/post-install scripts on Alpine

nfpm maps the `preinstall`/`postinstall` scripts to APK's `.pre-install` /
`.post-install` hooks. The existing `packaging/scripts/preinst.sh` and
`packaging/scripts/postinst.sh` are reused.

## 2. AUR PKGBUILD

### 2.1 File location

```
packaging/aur/
├── PKGBUILD
└── .SRCINFO          # generated by makepkg --printsrcinfo
```

### 2.2 PKGBUILD structure

```bash
# Maintainer: skoed maintainers <maintainers@skoed.io>
pkgname=skoed
pkgver=<semver>            # updated by CI on each release
pkgrel=1
pkgdesc="Self-hosted DNS filtering with multi-node sync"
arch=('x86_64' 'aarch64')
url="https://github.com/ashmonger/skoed"
license=('MIT')
depends=()
source_x86_64=("$pkgname-$pkgver-x86_64.tar.gz::https://github.com/ashmonger/skoed/releases/download/v$pkgver/skoed_${pkgver}_linux_amd64.tar.gz")
source_aarch64=("$pkgname-$pkgver-aarch64.tar.gz::https://github.com/ashmonger/skoed/releases/download/v$pkgver/skoed_${pkgver}_linux_arm64.tar.gz")
sha256sums_x86_64=('SKIP')   # replaced by CI with real checksums
sha256sums_aarch64=('SKIP')
package() {
  install -Dm755 skoed "$pkgdir/usr/bin/skoed"
}
```

### 2.3 Version sync in CI

The release workflow runs a step after goreleaser that:
1. Reads the released version from the goreleaser `dist/metadata.json`.
2. Patches `pkgver` and `sha256sums_*` in `packaging/aur/PKGBUILD`.
3. Regenerates `.SRCINFO` via `makepkg --printsrcinfo`.
4. Pushes the updated files to the AUR SSH remote (`aur.archlinux.org:<pkgname>.git`)
   using the `AUR_SSH_PRIVATE_KEY` repository secret.

If `AUR_SSH_PRIVATE_KEY` is absent (e.g., forks or local dev), this step is
skipped without failing the workflow.

## 3. Helm chart

### 3.1 Chart location

```
charts/skoed/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml        # or daemonset — controlled by values.kind
│   ├── service.yaml
│   ├── configmap.yaml
│   ├── persistentvolumeclaim.yaml
│   └── _helpers.tpl
└── README.md
```

### 3.2 Chart.yaml

```yaml
apiVersion: v2
name: skoed
description: Self-hosted DNS filtering with multi-node sync
type: application
version: 0.1.0        # chart version (bumped independently of app version)
appVersion: "0.5.0"   # skoed binary version
```

### 3.3 Default values

```yaml
replicaCount: 1
image:
  repository: ghcr.io/ashmonger/skoed
  tag: ""              # defaults to Chart.appVersion
  pullPolicy: IfNotPresent

kind: Deployment       # or DaemonSet

service:
  type: ClusterIP
  dnsPort: 53
  apiPort: 8080

persistence:
  enabled: true
  size: 1Gi
  storageClass: ""

config: |
  node:
    id: "skoed-0"
    api_address: "0.0.0.0:8080"
    dns:
      listen:
        port: 53
        ipv4: true
        ipv6: true
    data_dir: "/var/lib/skoed"

resources: {}
nodeSelector: {}
tolerations: []
affinity: {}
```

### 3.4 OCI publishing

goreleaser does not natively support Helm publishing. A separate step in the
release workflow handles this:

```yaml
- name: Publish Helm chart to GHCR
  run: |
    echo "$GITHUB_TOKEN" | helm registry login ghcr.io -u "$GITHUB_ACTOR" --password-stdin
    helm package charts/skoed --version "${{ steps.version.outputs.tag }}" --app-version "${{ steps.version.outputs.tag }}"
    helm push skoed-*.tgz oci://ghcr.io/ashmonger/charts
```

The chart is then pullable as:
```sh
helm pull oci://ghcr.io/ashmonger/charts/skoed --version <version>
helm install skoed oci://ghcr.io/ashmonger/charts/skoed --version <version>
```

## 4. Proxmox script in release artifacts

goreleaser's `extra_files` section attaches arbitrary files to the release:

```yaml
extra_files:
  - glob: scripts/proxmox-create.sh
```

The file is included in the GitHub Release alongside the .deb, .apk, and tar.gz
artifacts.

## 5. CI release workflow additions

The existing `.github/workflows/release.yml` is extended with three steps after
the goreleaser step:

1. **Helm publish** — packages and pushes `charts/skoed` to GHCR OCI (§3.4).
2. **AUR sync** — patches PKGBUILD + pushes to AUR if secret is set (§2.3).
3. **Docs trigger** — dispatches the docs workflow so Pages is rebuilt with the
   new version metadata immediately after a release.

No new workflow file is required; all additions are steps in the existing job.
